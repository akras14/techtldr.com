Voytko grants that software is degrading now, since 10x more code with an unchanged error rate means a buggier production app. But he rejects the nostalgia that software used to be better. Using computers since 1990, he remembers it as unreliable, with a few exceptions like Carmack-style programmers who weren't writing most of what people used.

His examples:

- **Crashes:** Windows blue screens from buggy drivers and leaked resources were routine, and apps without autosave (or with autosave that corrupted files) lost hours of work. On the Google Docs team in 2010, the no-op Ctrl+S shortcut was still a top-5 non-editing action.
- **Security and upkeep:** screensaver locks could be bypassed with Ctrl+Alt+Del, adware piled up, macro viruses hit the Internet, and users had to run Disk Defragmenter by hand.
- **Fragile distribution:** software shipped once on floppies, CDs or ROMs, which set a quality floor but also meant scratched media or rusted cartridge contacts killed it. Memory limits caused bugs like a game crashing past 255 units.
- **Games and hardware assumptions:** Diablo II had client-side hacks and item duping, and apps timed to a 4.77MHz clock needed a TURBO button.

He concedes modern software is bloated, slow and complex, and that agents are loosening developers' grasp of how it works. Still, he prefers process isolation, online updates, higher-level languages and Windows Update to the old release process.
